01Context

Leadership needs a fast, trustworthy read on financial and operational performance. The underlying data lives in SAP and other business systems — rich, but not shaped for decision-making.

02Problem

How do you take large volumes of SAP data and present revenue, EBITDA and margin across multiple periods and comparisons — MTD, QTD, YTD, MoM, QoQ, YoY — without overwhelming a CFO who has minutes, not hours?

03My role

UI/UX Designer — responsible for the information architecture of the dashboard, KPI hierarchy, chart selection and the visual design, specified for implementation with ApexCharts.

  • Figma
  • Claude AI
  • ApexCharts

04Research & understanding

  • Listed the decisions management makes and the KPIs behind each one.
  • Mapped which SAP data feeds which metric, and at what granularity.
  • Defined period and comparison logic so every number reads the same way across the product.

05UX process

  1. 01Established a KPI hierarchy: headline numbers first, trend second, breakdown on demand.
  2. 02Designed a consistent period switcher (MTD / QTD / YTD) and comparison model (MoM / QoQ / YoY).
  3. 03Matched each question to the right chart type and specified them for ApexCharts.
  4. 04Structured drill-downs so detail is reachable without cluttering the overview.

06Wireframes

Layout studies for the KPI strip, trend charts and drill-down tables — testing what management should see in the first five seconds.

07Visual design

A restrained palette where colour carries meaning (growth, decline, target), clear number formatting and a type scale tuned for large figures.

08Prototype

A clickable prototype covering period switching, comparisons and drill-downs, used to review the experience with stakeholders before build.

09Development

Chart specifications and component behaviour documented for implementation with ApexCharts.

10Result

  • A clear KPI hierarchy for financial and operational performance.
  • Consistent period and comparison logic across every view.
  • A dashboard structure that can scale as more SAP data sources are added.

11Learnings

Data visualisation is mostly information architecture. Agreeing on definitions and comparison logic early mattered more than any individual chart.
